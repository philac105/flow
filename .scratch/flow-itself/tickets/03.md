## What to build
The core loop. `flow next` prints what to do now for a Run: the current Stage's
name, its description, and the literal Command string to run. `flow done`
records the current Stage complete, advances to the next, rewrites the `## Where
we are` Handoff block, and appends one entry to `## Log`.

`flow done -m "..."` supplies the Handoff text and the Log entry. The Handoff is
always rewritten in place; the Log is only ever appended to. Nothing in the code
may special-case a Stage by name (ADR-0003), and `flow next` must never execute
the Command (ADR-0001) — it prints it.

## Acceptance criteria
- [ ] `flow next` prints the current Stage's name, description and Command
- [ ] `flow next` on a Run at its last completed Stage says the Run is finished
- [ ] `flow done` advances the Run's position by one Stage
- [ ] `flow done` rewrites the Handoff block rather than appending a second one
- [ ] `flow done` appends a Log entry carrying the Stage name and a timestamp
- [ ] Existing Log entries survive verbatim across many `flow done` calls
- [ ] No process is spawned by `flow next` — assert the Command is printed, not run
- [ ] With a single Run present, `next` and `done` work without naming it
