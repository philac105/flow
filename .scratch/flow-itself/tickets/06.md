## What to build
The non-linear moves. `flow skip` marks the current Stage skipped and advances
(refused when the Stage is not `optional`). `flow back [<stage>]` moves a Run to
an earlier Stage — the review-kicks-back-to-implement case. `flow finish` marks
a Run done so it drops off the default board.

Each of these rewrites the Handoff and appends a Log entry, exactly as `done`
does, so history stays honest about reversals.

## Acceptance criteria
- [ ] `flow skip` advances past an `optional` Stage, marking it skipped
- [ ] `flow skip` on a non-optional Stage exits non-zero and changes nothing
- [ ] `flow back` moves to the previous Stage; `flow back <stage>` to a named one
- [ ] `flow back` re-opens the target Stage as `in_progress`
- [ ] `flow back` appends a Log entry recording the reversal, deleting nothing
- [ ] `flow finish` sets the Run's status so `flow status` hides it by default
- [ ] All three rewrite the Handoff block
