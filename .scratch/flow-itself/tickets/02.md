## What to build
`flow start "Auth rework" --kind feature` creates `.flow/runs/auth-rework.md`
with TOML frontmatter (slug, title, kind, flow, status, timestamps, one record
per Stage from the Flow) and a body containing a `## Where we are` Handoff block
and an empty `## Log` section. `flow show auth-rework` reads that file back and
prints the Run's position, Handoff and Log.

The round trip must cross a process boundary — `start` in one invocation, `show`
in another — because that is the property the whole tool rests on.

## Acceptance criteria
- [ ] `flow start` derives a slug from the title and writes `.flow/runs/<slug>.md`
- [ ] Frontmatter round-trips: every field written is read back identically by
      a separate `flow show` process
- [ ] The first Stage is `in_progress`, every later Stage is `pending`
- [ ] `--kind` is free text and is stored verbatim; omitting it is allowed
- [ ] `flow start` with a title colliding with an existing Run fails with a
      clear message rather than overwriting
- [ ] `flow show` on an unknown slug exits non-zero with a clear message
