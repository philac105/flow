## What to build
Running `flow init` in an empty repo leaves a `.flow/flow.toml` on disk holding
the default Preset's Stages, and a `.flow/runs/` directory. Re-running it does
not clobber an existing `flow.toml`.

This is the walking skeleton: the cargo project (`runflow` crate, `flow`
binary), the clap command surface, the TOML types for a Flow and its Stages, and
the integration-test harness every later ticket uses (`assert_cmd` driving the
real binary against a `tempfile::TempDir`).

The Preset ships in the binary via `include_str!` and is written out verbatim,
per ADR-0003 — the code must not resolve Stages from a built-in structure at
read time.

## Acceptance criteria
- [ ] `cargo build` produces a `flow` binary
- [ ] `flow init` in an empty dir writes `.flow/flow.toml` and `.flow/runs/`
- [ ] The written `flow.toml` parses back into the Flow types
- [ ] The default Preset has the five main-flow Stages, each with name,
      description, command and artifact
- [ ] `flow init` a second time leaves an edited `flow.toml` untouched and exits 0
- [ ] `tests/cli.rs` exists and drives the compiled binary against a tempdir

## Blocked by
None — can start immediately.
