# flow-folder — grill

What `.flow/` holds, who owns it, and what happens to a run once it is done.
Five rounds. Every decision below was put to the person who asked for the work
and answered; where a recommendation was overturned, that is noted.

## The three things that started it

1. Finished runs should maybe get deleted.
2. `flow.toml` should maybe be a link to a preset rather than a full file.
3. `runs/` should maybe be gitignored — it is user state, not app state.

One of the three produced a change. One was answered and closed. One was
deliberately declined, and that is recorded at the bottom.

## Decisions

### Layout

**D1 — Stage artifacts live at `.flow/artifacts/{slug}/<stage>.md`.**
All three shipped presets adopt it. `.scratch/{slug}/` (used by `main-flow`)
and `.flow/notes/{slug}.md` (used by `minimal` and `bugfix`) are both retired.
The presets disagreed with each other, which is the only reason `.scratch/`
exists at the repo root. `artifacts` is the name because the glossary already
defines **Artifact** and drift-checking is literally a check of the `artifact`
path — `notes` was a third word for a concept that had one.

Nothing in `src/` mentions either old path: both are pure `flow.toml` data, so
this is a preset-content change, not a code change. Existing repos own their
`flow.toml` (ADR-0003) and are untouched.

**D2 — `.flow/flow.toml` stays a full, self-contained copy.**
No link to a preset, no provenance field, no `extends`, no `flow update`, no
`flow diff`. ADR-0003 and ADR-0008 stand unamended.

The reason a link was rejected: `preset = "main-flow"` resolves through the
Preset Path at read time, so the flow a repo follows would depend on who cloned
it. A teammate with their own `main-flow.toml` in `~/.config/flow/presets/`
would silently get a different flow out of your repo — and presets are not inert
data, they can carry launcher argv, which is the same hazard that gave the
preset walk its ceiling in ADR-0008.

### Lifecycle

**D3 — Runs stay committed by default; ignoring them is the user's call.**
The `Handoff` is defined as the first thing a cold agent reads and the `Brief`
as the only context the first stage has; both readers are typically on another
machine or in another session. A gitignored `runs/` makes `flow status` on a
fresh clone print "no runs yet". ADR-0002 stands.

**D4 — No archiving, no deletion. `flow finish` is unchanged.**
No `.flow/runs/archive/`, no `flow delete`, no `flow prune`. `rm` is the
command. Archiving was recommended in round 2 and *withdrawn in round 3* once
the artifact consequence surfaced (see D5): filing the run file while its
artifacts stay put is half a move, and taking the artifacts along means
rewriting the record.

**D5 — Flow never rewrites a recorded artifact path. A human may.**
`Run::drift` (`run.rs:178`) trusts `record.artifact` — the path stored when the
stage completed — over the stage's declaration in `flow.toml`. That record is
evidence of what happened. The tool must not edit it; a person performing a
one-off migration can, which is what makes D8 possible without leaving
permanent drift. This distinction is the load-bearing one: it is why D4 forbids
an automatic move while D8 performs a manual one.

### Gitignore

**D6 — The `.flow/.gitignore` that `init` writes gains two commented-out
blocks.** `/runs/` and `/artifacts/` under one comment explaining the
trade-off; default is committed. `/board.html` is ignored outright — it is
generated by `flow board`, regenerable from the run files, and `--output`
exists for anyone who wants it elsewhere.

Artifacts get the same presented-choice treatment as runs rather than being
silently ignored or silently committed, because they are the same *kind* of
decision — this checkout's working state versus the project's record.

**D7 — `init` writes `.flow/.gitignore` only when absent.**
Prints `kept .flow/.gitignore (already yours)` otherwise, the treatment
`flow.toml` already gets. Today it is an unconditional `std::fs::write`
(`init.rs:41`), which is harmless only while the content is a fixed one-liner;
the moment D6 invites the user to edit it, re-running `init` silently reverts
their choice, against ADR-0004's claim to be idempotent.
`.claude/skills/flow/SKILL.md` keeps being overwritten unconditionally — it is
ours and must track the protocol. Different owner, different rule.

### This repo's migration

**D8 — Move the 13 tracked files under `.scratch/` and correct the records.**
- `git mv .scratch/flow-itself .flow/artifacts/flow-itself`
- `git mv .scratch/presets-folder-3 .flow/artifacts/presets-folder-3`
- Hand-edit the recorded `artifact` paths in `.flow/runs/flow-itself.md` and
  `.flow/runs/presets-folder-3.md` so they point at the new locations. Leaving
  them pointing at `.scratch/…` would be the lie drift exists to catch.
- Point `.flow/flow.toml`'s `grill` stage at `.flow/artifacts/{slug}/grill.md`.
- `git rm --cached .flow/board.html`.
- This run's own grill artifact is written to `.scratch/flow-folder/grill.md`,
  where the flow as it stands today says it goes, and moves with the rest.

## Code surface added

**None.** D6 and D7 touch `src/commands/init.rs`. D1 is preset content. D8 is a
one-time migration. Everything else is a decision not to build something.

## ADR

`docs/adr/0009-flow-state-is-one-folder-that-flow-never-prunes.md` carries D1,
D4 and D5 under one principle, and records the archive/delete/gitignore-by-
default options that were considered and rejected. It exists mainly because the
next person to look at `.flow/runs/` will propose archiving — as happened here.

No `CONTEXT.md` change. The only new domain noun this session produced was
*Archive*, and it was rejected.

## Deliberately not done

**Pulling preset improvements into an existing repo.** A repo that ran `init`
keeps its flow forever, and there is still no way to read a shipped preset —
they are embedded in the binary by `build.rs`, and `flow presets` prints name,
layer and description but never contents (`config.rs:119`). So you cannot see
what changed in `main-flow` without running `init` into a throwaway directory.

Two fixes were proposed and both declined: `flow update` with provenance and
merge semantics (round 2 — rejected as the machinery ADR-0008 already turned
down for `extends`), and `flow presets --show <name>` printing a preset to
stdout so the shell could diff it (round 5 — "not required yet").

This is a known gap, seen and declined, not an oversight. If it comes back,
`flow presets --show` is the cheap end: a print primitive, no diff algorithm in
the tool, and `flow presets --show main-flow | diff .flow/flow.toml -` gets you
the rest.
